# Write attribution probe (#901)

Measurement tools that attribute a running dashboard's disk writes to files, threads and SQL statements without root. They produced the root-cause evidence in `docs/superpowers/specs/2026-10-03-901-dashboard-disk-writes.md` §1 and are the production-scale acceptance method of its §6.3. They are maintainer-local measurement tools, never part of the product.

## Pieces

- `wtrace.c` — a `DYLD_INSERT_LIBRARIES` interposer over `write`/`pwrite`/`writev`/`pwritev`/`close`. It resolves each descriptor with `F_GETPATH`, accumulates bytes per path, keeps per-thread SQLite temp-file (`etilqs_*`) and other-file counters, and dumps cumulative per-path totals every `WTRACE_PERIOD` seconds (fractional allowed) to `$WTRACE_OUT.<pid>` (plus `.<pid>.exit` at exit). Closes and snapshots share one lock, so no close is lost to a concurrent snapshot, and bytes that fit no table slot are reported as `dropped` rather than discarded. It also keeps the **WAL frame log** the deletion receipts read: every 24-byte frame-header write to a `-wal` file (and every WAL header write) becomes a `{t, path, frame, pgno, commit, salt}` record in a bounded ring flushed with the snapshots to `$WTRACE_OUT.<pid>.frames`; a record that finds the ring full is counted in the snapshot's `framesDropped` and `dropped`, which invalidates the run. Every snapshot carries the process's `footprintPeak` (`ri_lifetime_max_phys_footprint`), so the exit snapshot of every interposed process, workers included, is its terminal high-water mark. Build: `clang -O2 -dynamiclib -o wtrace.dylib wtrace.c` (the runners build it into the scratch directory). It loads into Homebrew Python, which is ad-hoc signed without the hardened runtime; it does not load through SIP-protected launchers such as `/usr/bin/env` or `/usr/bin/time`, so call the interpreter directly.
- `selftest.py` — the interposer's regression: a snapshot held open (`WTRACE_TEST_PAUSE_US`) while another thread closes a written temp file, a four-thread write/close stress under continuous snapshots, a WAL-mode commit whose logged frames must equal the WAL file's frames exactly, a four-record ring that must count its drops, and the footprint field. Exit 0 and `selftest: PASS`, or exit 1.
- `analyze_selftest.py` — the analyzer's regression: nine synthetic runs (valid; failed endpoint samples; all samples failed; a counter reset; sparse coverage; missing and failed self-test receipts; a decreasing trace path; a dropped snapshot).
- `sqlattr.py` — runs `bin/cctally <args>` in-process with `sqlite3.connect` patched to install `set_trace_callback`, and charges each thread's temp-file and other-file bytes to the statement and `bin/` call site that was running. Each thread's final interval is flushed (at thread end, and the main thread's at exit), every statement is kept (`stmts`; `top` is the 200-row display), and at exit the interposer's own process total gives an explicit `unattributed` bucket, so attributed + unattributed reconciles with the per-process total. `SQLATTR_TEMP_STORE=DEFAULT` is the labelled FILE-control for the statement-journal evidence. Output: `$SQLATTR_OUT` (JSON, refreshed every 10 s, final at exit, with the process's peak footprint).
- `rusage.py PID…` — `proc_pid_rusage(RUSAGE_INFO_V4)` disk bytes (the counter the issue used), resident, physical-footprint and lifetime-peak bytes. A failed read emits `rc`/`errno` and `null` counters, never zeros.
- `jsonl_bytes.py [--baseline FILE]` — total bytes of the Claude and Codex transcript JSONL roots the run reads, for the "proportional to new data" denominator and the ambient-growth label; with `--baseline` (revision 15) also per-file growth (`grown`, `new`) and discontinuities (`shrunk`, `replaced`, `deleted`) against a baseline written on its first call, which aggregate totals could hide. In a frozen run it is a family process, so it measures the freeze, whose growth must be zero.
- `rootmap.c` — the frozen read namespace (spec §6.3 "Frozen namespace", revision 15, Q16): a `DYLD_INSERT_LIBRARIES` interposer loaded before `wtrace.dylib` that redirects every read under a frozen logical root to the sealed freeze and answers with the captured source device, inode, admitted size and timestamps through `stat`, `fstat` and directory entries, and the logical spelling through `realpath`, `getcwd` and `F_GETPATH`. An unmapped path under a root fails closed (EACCES and an `unmapped` receipt event), a recorded absence returns ENOENT, any write intent is denied. It interposes `open`, `open$NOCANCEL`, `openat`, `openat$NOCANCEL`, `stat`, `lstat`, `fstat`, `fstatat`, `access`, `faccessat`, `opendir`, `__opendir2`, `fdopendir`, `readdir`, `readdir_r`, `readlink`, `readlinkat`, `realpath`, `realpath$DARWIN_EXTSN`, `fcntl(F_GETPATH)`, `chdir`, `getcwd`, `execve`, `posix_spawn` (re-injecting a namespace a child's environment lost, and recording each launch with its program, `#!` interpreter, bounded arguments, parent and child pid), `waitpid`, `wait4`, `wait3`, `wait` and `waitid` (the parent records each child's termination status, so a child the sandbox kills is visible even when its parent ignores the failure), `kill` and `killpg` (which family member sent a signal) and `_exit`, never a write function, and writes one activation receipt per process (`<pid>.<start_s>.<start_us>.jsonl`) through raw system calls; its `enforced` list proves the sandbox denies every root (one file root per out-of-root link target) and every non-traversed directory link's live target (`X` records, `denyOnly`). `readlink` of a link's logical spelling returns the stored target, of its frozen spelling the frozen link itself, so libc's `realpath` stays inside the freeze.
- `frozen_roots.py` — `capture` (the frozen input set of one measurement session, bound to every closed store copy it serves, `--store` once per copy, with each copy's identity in the manifest's `stores`; walked rollouts and Claude projects as record-boundary prefixes at or beyond every cursor and scan target any bound copy retains, metadata whole by a stable read, recorded absences, symlinks covered or refused (Amendment 10: a file link inside a root by that root's file, an absolute single-hop link to a regular file outside every root by its target's own single-file root, a directory link the walk never traverses as a non-traversed link whose live target the profile denies); writes `manifest.json`, `rootmap.tsv`, the sandbox profile `frozen.sb` and `seal.json`, and makes the freeze read-only), `verify` (the seal, before and after every run; `--full` re-hashes content), `qualify` (once per bound copy: refuses a copy the freeze is not bound to, and a copy whose retained cursor, scan target, inode or committed prefix does not fit the freeze, that copy only), `family` (every process of a run activated this freeze's namespace under sandbox enforcement and recorded no unmapped or denied access, every process started through a protected system program is admitted only by its launch and termination records and listed, and no family member ended on an unrecorded signal), `reap` (the bounded teardown, recording each kill in `teardown.jsonl` first) and `inputs` (the run's `inputs.json`).

## Rules

- **Bounded and stopped.** Every runner kills the dashboard after its duration, and its guard (`_inputs.sh` `wa_guard`) kills the whole family — detached workers included — on every exit, at its hard deadline, and through its watchdog if the runner itself is killed. Never leave one running against a live installation; wrappers (`run-p2.sh`, `run-p3.sh`, `run-lifecycle.sh`) forward an interrupt to the runner they wrap (`wa_child`).
- **Loopback only.** Runners pass `--host 127.0.0.1`; a copied `config.json` may say `dashboard.bind = lan`.
- **Spare the internal SSD.** Set `WRITE_ATTRIBUTION_SCRATCH` to a directory on an external drive; runners put `TMPDIR` (SQLite temp files) and their outputs there. Keep store copies there too (`cp` across volumes, or `cp -c` within the external volume).
- **Copies, not the live store,** except `run-live.sh`, which is an operator-authorized confirmation run of the installed dashboard. Copy SQLite databases with the backup API from a read-only connection (`cp -c` is fine for cloning a closed scratch copy).
- **Fail closed.** A run without a passing self-test receipt, or one the analyzer marks `INVALID`, is not evidence.
- **An explicit input mode.** Every runner refuses to start without `WRITE_ATTRIBUTION_INPUTS=frozen:FREEZE` or `WRITE_ATTRIBUTION_INPUTS=live`; only `run-live.sh`, `run-scratch-proof.sh` and `run-workload.sh L` are live by definition, and any other runner takes live inputs only with an explicit `--live`. Every verdict (`analyze.py`, `analyze_op.py`, `workload.py`, `projection_replay.py p1-verdict`) requires the run's `inputs.json` and names its evidence (frozen and its seal, or live); a frozen run whose family is incomplete, whose freeze changed, or whose inputs grew is INVALID, and a comparison across two freezes (or frozen against live) cannot PASS.

A frozen window's leak check counts only changes at or under a logical root of the run's freeze (`manifest.json` `roots`, link-target file roots included), using the last in-window sample's per-file `changes`; a change outside every freeze root is the run's controlled input (B's and D's `ROOT/scratch`) and is reported separately, and without a readable manifest or per-file changes every change counts (Amendment 15 Q1). `_prep.sh` runs the write-attribution self-test, `frozen_selftest.py` with the run's tree and `frozen_roots.py verify`, then writes `inputs.json`; every family process starts through `sandbox-exec -f FREEZE/frozen.sb python3 frozen_launch.py … -- TARGET`, and `wa_finish` reaps the family, re-verifies the freeze and judges its activation receipts (`frozen-family.json`). A run with an `unmapped` read, a lost receipt, absent enforcement or frozen growth is INVALID: find the input it names, recapture with `--extra`, and run again. Processes started through protected system programs (Q17, the operator's decision): macOS keeps the library out of an executable under `/bin`, `/sbin`, `/usr/bin`, `/usr/sbin`, `/usr/libexec` or `/System`, or a `#!` script whose interpreter is one (`npm prefix -g` through `/usr/bin/env`, which the product's own `cache-sync` runs; `lsof` or `ps` on maintenance paths), so such a process and any image it executes run without activation, inside the inherited sandbox, outside the write interposer and the per-process I2 statistics. `family` admits one only when its parent's launch record names the program, the arguments, the parent and the child pid and the parent recorded its termination status, and lists each in `admittedSystemPrograms` (`frozen-family.json`, `inputs.json`); a system program without either record, and any other process that never activated, is INVALID, and the list never discharges a missing activation. A signal termination of a family member, covered or admitted, whose exact signal a recorded family member sent to that child (rootmap's `kill`/`killpg` record; for example the product's `npm prefix -g` timeout kill after 2 s) is listed under `familyKills` (`frozen-family.json`, `inputs.json`) and does not invalidate the run. A signal no family member sent stays fatal (`signalTerminations`), including when a member sent that child a different signal: the sandbox kills a violating process with SIGKILL and logs nothing, so a parent that swallows its child's failure would otherwise hide a namespace leak. The harness's own teardown kills are distinguished as well: `frozen_roots.py reap` and the runners' `wa_kill` record each in `RECEIPTS/teardown.jsonl` before sending it (`wa_kill` records nothing for a process that has already ended, so a sandbox kill is never relabelled as teardown), and `family` counts those as `teardownKills`. A top-level family process — one a runner starts through `wa_exec` — has the runner's shell as its parent, which the namespace does not load, so no member records how it ended (Amendment 13 O3: a catch-up killed after its `cache-sync` child exited 0 left the family VALID). Every runner therefore starts each one in the background and waits on it with `wa_wait STEP PID`, which appends to `RECEIPTS/toplevel.jsonl` one line per end, schema `toplevel/1`: `pid`, `status` (the shell's wait status), `exited`, `code`, `signaled`, `signal` (a status above 128 is signal `status − 128`), `runner` (the script), `step` and `t`; `hook_runner.py` records each hook child the same way (a negative returncode is the signal). `family` judges a signal there by the same rules as a member's (a recorded teardown kill and a signal a recorded member sent are exempt, listed under `teardownKills` and `familyKills`; any other is INVALID and listed in `signalTerminations` with `topLevel: {runner, step}`), reports `topLevel: {records, signaled, unrecorded}`, and requires an end record for every pid in `launches.jsonl`, so a runner path that ends one unrecorded is INVALID rather than silent.
